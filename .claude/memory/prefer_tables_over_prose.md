# Presentation: comparison TABLES, not long paragraphs

Origin: user feedback (2026-08-04) on the p3 `novelty_gap` draft. The user rejected a multi-sentence
"gap" paragraph and asked for comparison tables, saying long prose is hard to eyeball.

## Rule
Convert paragraphs to TABLES aggressively, not just obvious comparisons: any explanatory or
definitional block of 3+ points becomes a table. Keep standalone prose to single-line callouts
(a question or a one-sentence claim is fine; a multi-sentence paragraph is not). Add an emoji to
EVERY table row (the user asked for "as many emojis in each row as possible"), ideally in more than
one cell. Mermaid diagrams also welcome. The user reinforced this TWICE on 2026-08-04: first
rejected a gap paragraph, then rejected a research-language paragraph, both times demanding tables
plus per-row emojis.

## Scope
Applies to WORKING docs (novelty_gap, analyses, status reports, comparisons). The PUBLISHED survey
still uses academic prose (CSUR style). Related: em-dashes are also banned everywhere (see the
block_em_dash hook).
